# 게이트 2-5 (a) 4차 검토 — 테스트 코드 전체 직접 읽기 @ `6a748b6`

## 결론

- 저장소의 Rust 테스트 코드 전부를 서브에이전트 없이 직접 읽었다: `tests/` 디렉터리의 파일 29개(약 3만 5천 줄)와 `crates/*/src`의 인파일 `#[cfg(test)]` 모듈 전부. 읽지 않은 것은 5절에 있다.
- **P0 0건, P1 0건.** 데이터 손실이나 잘못된 수락으로 이어지는 제품 결함은 찾지 못했다.
- **P2 30건**(A 10, B 6, C 11, D 3). 그중 15건은 스크래치 클론에서 소스를 깨뜨린 뒤 해당 테스트가 그대로 통과하는 것을 확인했고(변이), 1건은 테스트에 카운터를 넣어 확인했다(계측). 나머지는 읽기와 grep이다.
- T6 표 33행(45개 위치)을 38개 판정으로 나눠 모두 판정했다: 확인 33, 부분 확인 1, 반박 2, 이미 수정됨 1, 낡음 1. 각주 4건은 모두 확인했다.
- **게이트 (a)가 닫혔다고 주장하지 않는다.** 이 검토는 한 번의 통독이고, 변이는 후보로 고른 것만 돌렸다. 전체 스위트를 변이마다 돌리지 않았고 Linux에서는 아무것도 실행하지 않았다.

심각도 기준: P0 데이터 손실·잘못된 수락, P1 실제 경로의 잘못된 동작 또는 P0 경로의 테스트 공백, P2 나머지. 확인 방법은 **변이**(소스를 깨고 `--exact`로 실행, "1 passed" 확인), **계측**(테스트에 카운터 삽입), **읽기**(읽기 또는 grep)로 표시한다.

- **비테스트 본문**: 4절에 적힌 줄 밖의 소스는 읽지 않았다. "테스트가 없다"는 판정(B1~B3, B6, 각주 #340·#344·#339)은 grep에 기댄다.
