# brgr v2.15.12

`brgr prune` and the decision-time cleanup leave fewer settled workers behind: tool-state directories no longer block a worktree, and a branch whose work was squash-merged can be pruned.

## What changed

- A worktree whose only ignored or untracked leftovers are tool-state directories (`.agent-progress/`, `.build/`, `.commandcode/`, `.gjc/`, plus the nine dependency and build directories already covered) is removed without `--include-ignored`. The same names get the same verdict whether git reports them as ignored or untracked. A file with such a name, `.build-notes.txt`, `.buildx/`, `dist/`, `build/` and any other ignored path such as `.env` still keep the worktree. `--include-ignored` behaves as before.
- `brgr prune` removes a settled task branch when every change in `git diff --binary MERGE_BASE TIP` (changed lines, mode changes, renames, created and deleted files) is also in the `text/x-diff` the store sealed with the result (`--capture-diff`), even when its commits are not in `HEAD` or on another branch, as after a squash merge or `brgr apply`/`land`. The report names the sealed result id. A missing merge-base, a binary patch, a change the sealed diff does not hold, or any error keeps the branch.
- Accepting or rejecting never removes a branch on that basis, because the branch is how you push the work. Only an explicit `brgr prune` does.

## What was checked

- Each change was verified in its own worktree with fmt, clippy `-D warnings` and the full workspace tests, with the diffs read. CI passed on both pull requests. Tests were written before the fix and seen failing, including a regression where the first design deleted the branch at `accept`.
- Not checked: a live `brgr prune` with this build against a real squash-merged remote branch; the sealed-branch rule is covered by fixture-based tests only. Several tests fail rarely in full parallel runs and pass alone; they are listed in issue #224 (12 so far, cause unknown).

## Compatibility

No store schema or config change. `brgr prune` can now delete a branch it used to keep; the sealed diff stays in the store and `brgr diff TASK` recovers it.
