# brgr v2.15.14

A Codex session that shares a Codex daemon started by a brgr worker is no longer refused for that worker's identity, and the incoming head of a handoff no longer inherits it.

## What changed

- `--as SESSION` (and `--owner-session`) ignores `BRGR_PARENT_TASK_ID` and `BRGR_PARENT_ATTEMPT_ID` from the environment when `BRGR_SESSION_ID` names a **different** session, and prints one note on stderr. A shared Codex daemon keeps the variables of the worker that started it, so every Codex session on that daemon was refused with `delegation parent attempt is stale, mismatched, or owned by another worker`. A delegated child that passes `--as` with its own `BRGR_SESSION_ID` is still checked and still refused when its parent is stale or mismatched; the store-side check is unchanged.
- The commands a handoff gives the incoming head now start with `env -u BRGR_SESSION_ID -u BRGR_PARENT_TASK_ID -u BRGR_PARENT_ATTEMPT_ID`, so the incoming head falls back to its own `CODEX_THREAD_ID` or `CLAUDE_CODE_SESSION_ID`.
- Tests only: the fake `#!/bin/sh` executables in the `brgr-cli` integration tests are hard links of one warmed trampoline, so they no longer wait for macOS to scan each new executable (about 200 ms each, one at a time). On the worker's measurement, 32 distinct scripts started at once took a median 3.8 s the old way and 0.11 s now.

## What was checked

- Each change was verified with fmt, clippy `-D warnings` and the relevant tests, with the diffs read, and CI passed on each pull request. The `--as` change has a pure-decision unit test, a black-box run against a stale foreign parent, and a test of the handoff prompt prefix, each seen failing first.
- In a real Codex pane against a daemon that still carried a worker's variables: before the change `brgr --as SESSION run` failed with the stale-parent error; with it the error was gone and the note appeared.

What was not checked: the whole Codex head flow. After the stale-parent error the run stopped at `default TUI execution needs an exact Herdr source`, because `brgr doctor` reports `codex_trace: not verified` for the Codex release on that Mac (0.162.1, verified baseline 0.160), so the screen-based identification of the calling Codex pane is not established there. The handoff prefix change was only tested with a fake Herdr. The test-speed change is a measured latency change, not a fix: the 20-run loaded repetition from issue #224 was not done, and whether the listed flaky tests fail for this reason is still unproven (full parallel runs on this Mac: 1 failure in 3 default runs and 0 in 3 capped at 6 threads, before this change).

## Compatibility

No store schema or config change. The handoff prompt text changes (an `env -u ...` prefix); an offer made by an older brgr still loads.
