# brgr v2.15.2

The live path of Head Migration: the current head opens a new head in its own
pane, the new head takes command, and the old head's pane can close after a
verified handoff.

## `brgr head handoff`, `take`, `exit`

`brgr head handoff TASK --kind claude --goal TEXT` runs inside Herdr. It records
an offer, opens a pane beside the head, starts the agent (a folder-trust prompt
is answered by the same screen rules workers use), and submits one prompt that
tells the incoming head to run `brgr head take TASK --offer KEY`. Nothing moves
until `take`.

`take` requests, prepares and commits in one step from the stored offer and the
store-built manifest. It refuses the outgoing session, an unknown offer, an offer
for another owner, and a head that moved since the offer. A repeat returns the
same record. The outgoing pane is told it is stale, but only while its agent is
idle.

`--exit-old` is approval, given at handoff time, to close the outgoing pane. It
runs only inside `retire`, after the store recorded `resumed` and the retire was
clean. The pane must still be the recorded terminal, must not be the incoming
head's own, and its agent must be idle or done. A refusal does not undo the
retire: the output says `outgoing_head.closed: false` with the reason, and
`brgr head exit TAKEOVER` retries. Workers are never closed.

## Verified

Unit and black-box tests pass, including six against a fake Herdr. In a real
Herdr pane with a scratch home, a Claude head took command, accepted the pending
result and retired the handoff; the store shows requested, prepared, committed,
resumed and retired. Closing the outgoing pane (`--exit-old`) was checked only
against the fake Herdr, not a real pane. Usage-triggered migration (roadmap 2.6)
is not in this release.

## Upgrade

```sh
cargo install --locked brgr-cli --version 2.15.2
brgr integrate claude install
herdr plugin install justn-hyeok/brgr --ref v2.15.2
```

No store migration. The macOS archive remains unsigned and not notarized.
