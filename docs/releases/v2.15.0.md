# brgr v2.15.0

Head Migration's abandoned-head path: another session can take command when
the current head cannot run brgr.

## `brgr head claim TASK --abandoned --goal TEXT`

The five-step handoff from v2.14.2 still stands when the outgoing session can
type (`request`, `prepare`, `commit`, `retire`). When it cannot, the incoming
session runs `claim --abandoned`. That records request, prepare, and commit in
one step, raises the binding epoch, and leaves the previous session stale.

`--abandoned` is required. Without it the command is refused; a live head uses
`brgr head request`. Repeating the same `--key` returns the same record.

Reaching `$BRGR_HOME` is the access check. The caller's `BRGR_OWNER_ID` may
name a different harness prefix than the stored owner (`claude:` vs `cursor:`).
After the claim, the bound session is the head. Workers are not closed.

Usage-triggered migration (roadmap 2.6) is not in this release. Closing the
outgoing commander pane is still a person or later work; claim never closes
workers.

## Upgrade

```sh
cargo install --locked brgr-cli --version 2.15.0
brgr integrate claude install
herdr plugin install justn-hyeok/brgr --ref v2.15.0
```

`brgr integrate` refreshes the installed skill so it mentions `head claim`.
No store migration. The macOS archive remains unsigned and not notarized.
