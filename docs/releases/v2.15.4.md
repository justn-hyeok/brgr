# brgr v2.15.4

Two fixes found by running `head handoff --exit-old` in real Herdr panes with
Claude, Codex and Cursor as the incoming head.

## Codex as the incoming head

A shared Codex daemon runs tool calls with its own environment, not the pane's.
On this machine it carried `BRGR_OWNER_ID=worker:…` from the worker it was started
under and no `BRGR_HOME`, so the incoming head could not find a custom home and
`head retire` refused with `BRGR_OWNER_ID differs`. The incoming prompt now starts
every command with `env BRGR_OWNER_ID=… BRGR_HOME=…`. The refusal of a mismatched
owner id is unchanged.

## Cursor as the incoming head

Cursor's trust box has single-key options and no menu, so no screen rule matched
and `head handoff` typed its prompt into the box. A rule now presses `a` for the
task's own workspace, only while the box waits for an answer; another directory
is reported, and a box already answered is left alone.

## Verified

Unit and black-box tests pass, each new test failing before its fix. In real Herdr
panes with a scratch home and a Claude outgoing head: Claude, Codex and Cursor each
took command from the automatic prompt alone, accepted the pending result and
retired, and the outgoing pane closed after the retire. A busy outgoing head was
not closed, and `brgr head exit` closed it once idle. Usage-triggered migration
(roadmap 2.6) is not in this release.

## Upgrade

```sh
cargo install --locked brgr-cli --version 2.15.4
brgr integrate claude install
herdr plugin install justn-hyeok/brgr --ref v2.15.4
```

No store migration. The macOS archive remains unsigned and not notarized.
