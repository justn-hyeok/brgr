# brgr v2.15.13

`brgr status --brief` gives an agent a short status, `brgr head handoff` works for a session that has no brgr tasks, and every group kill is safe on Linux.

## What changed

- `brgr status --brief` prints one line per task (full id, state, harness, elapsed, objective head), the same on a terminal and in a pipe, with no ANSI. `brgr status TASK --brief` prints the state, the last event, and whether a result and a decision exist. `--brief --json` is a compact array with a fixed key order. Without `--brief`, piped and `--json` output is byte-for-byte what it was. The skill and `status --help` now point agents to `--brief`.
- `brgr head handoff` no longer requires a TASK. Without it the handoff covers the calling owner's open tasks; with none, a session that has no brgr work still opens the new Head pane, with a manifest of only the goal and notes. `--help` names the task id format, and a malformed id hints at `brgr status`. `brgr head take` accepts an omitted TASK for the same reason. An explicit TASK behaves as before.
- Every `/bin/kill` call that signals a process group now passes `--` before the negative pid. Linux's `kill` read a bare `-<pgid>` as an option and signalled every process of the user (`kill(-1)`); macOS was never affected. A source scan test keeps a bare `-<pgid>` from coming back.

## What was checked

- Each change was verified with fmt, clippy `-D warnings` and the relevant tests, with the diffs read, and CI passed on each pull request.
- `status --brief` on a real store of 20 tasks: the piped `brgr status` was 858 lines and 168,028 bytes, `--brief` was 20 lines and 2,688 bytes, and the default piped output is the same 168,028 bytes with the old and new build.
- The group-kill change was checked on macOS only: `kill -0 -- -<pgid>` behaves normally and the runner, core and workflow-runner tests, including the one that kills a driver group, pass.

- The task-less handoff, in real panes with the release binary and a scratch home: a Claude Code head with no brgr tasks ran `brgr head handoff --kind claude --goal ... --exit-old`. The offer had no task, the new head took over and retired the handoff (the takeover row ended `retired`), the outgoing pane closed, and the pane that ran the test was untouched. No file named after a made-up task id was left in the runs directory. This is one run, Claude to Claude, with an empty manifest.

What was not checked: that `--brief` reduces an agent's calls or tokens; the group-kill fix on Linux, where `kill(-1)` was neither reproduced nor shown fixed; a task-less handoff whose outgoing head is Codex or Cursor, or whose manifest holds open tasks, in a live pane.

Known and not fixed in this release: some tests fail rarely in full parallel runs and pass alone (issue #224). The measured cause is that macOS runs the first execution of each new executable one at a time, about 200 ms each, so many tests that write a fake script at once wait on each other; which of the listed tests fail for that reason is not yet proven. A Codex session that shares a Codex daemon started by a brgr worker cannot run `brgr` (issue #240).

## Compatibility

No store schema or config change. `head handoff` and `head take` accept one argument fewer; old handoff offer files still load.
