# brgr v2.13.7

Landing a candidate in one command, and revising a run that failed.

## New

- **`brgr land TASK --workspace REPO --reason WHY`.** Reviewing a result and
  keeping its code took `accept`, then `apply --execute`, then a separate
  acknowledgement and cleanup. `land` checks the sealed diff against the
  repository first, and only if it applies records the accept and applies it. A
  diff that does not apply records no decision, so there is no accepted-but-not-
  applied state to untangle. `--3way` is passed through: the candidate is
  accepted and a conflict is left as markers, exactly as `apply --3way --execute`
  does, and the command exits with an error. If the apply fails after the
  accept, the error says so and names the `apply` command to retry.

## Fixes

- **A failed or lost run could not be revised.** `brgr revise` refused any
  result without an owner decision, and a failed or lost result has no candidate
  to decide, so the only way forward was a fresh `run` that lost the task's
  history. A revision now takes a failed or lost result as is, and counts as the
  owner's acknowledgement of it. A lost result warns that its worker may still be
  running or may have caused external effects. An accepted or cancelled result
  still cannot be revised.

## Worth knowing

- `accept` and `reject` already acknowledge the result they decide, in the same
  transaction, so no `result --ack` follows a decision. The docs now say so.
- The Codex skill's integrate step now mentions `land` and `--3way`. An installed
  copy shows as out of date in `brgr doctor` until `brgr integrate codex install`
  is run again.

## Upgrading

```sh
herdr plugin install justn-hyeok/brgr --ref v2.13.7
brgr integrate codex install   # refresh the installed skill
```

Existing commands behave as before.

The CLI archive remains unsigned and not notarized.
