# brgr v2.10.4

A native worker's harness variables, such as its API key, now come from the
worker's own pane shell instead of from the session that called brgr.

## Fixes

- A Command Code worker failed with "Insufficient credits" after the user had
  logged in again. brgr copied the allowlisted harness variables, including
  `COMMAND_CODE_API_KEY`, from the calling session into the worker. That session
  started before the stale key was removed from the shell profile, so the worker
  got the stale key and it overrode the new login. A native worker runs in a pane
  whose shell already has the user's current environment, so brgr now takes those
  variables from the pane and drops any that the pane does not set. Headless runs
  still pass the caller's allowlisted variables.

## Upgrading

Install v2.10.4.

```sh
herdr plugin install justn-hyeok/brgr --ref v2.10.4
```

The CLI archive remains unsigned and not notarized.
