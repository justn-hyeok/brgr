# brgr v2.12.8

Hotfix: worktree reclamation no longer force-deletes what a sealed patch cannot
hold.

## Fix

- A worktree whose patch matched the sealed diff was force-removed. Two things
  in a worktree are not in any patch:
  - a git repository nested inside it (a worker that cloned or started one
    under `vendor/`, say), which a patch records only as its commit id, so
    its uncommitted work was lost;
  - brgr's own `.brgr/` report directory, which is archived out of the
    worktree once the result is handled and is left out of the patch, so a
    report whose archiving failed was lost.
  Either now keeps the worktree. brgr also reads untracked files one by one
  (`--untracked-files=all`), since git otherwise folds `vendor/lib/` into
  `vendor/` and the nested repository is never seen.

## Upgrading

Install v2.12.8.

```sh
herdr plugin install justn-hyeok/brgr --ref v2.12.8
```

The CLI archive remains unsigned and not notarized.
