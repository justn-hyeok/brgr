# brgr v2.15.20

The gate 2-5 review of v2.15.19 reported eight P1 and twenty-one P2 findings, none P0. This release fixes every P1 and most P2s, chiefly around revisions, heads, installers and stopping a process.

This follows v2.15.19 on the same day. Releases no longer wait a day; only batching remains (#348).

## Before you upgrade

- **`BRGR_HOME` now wins inside a task worktree.** Only a command with neither it nor `--home` takes its home from the worktree's path. A stale `BRGR_HOME` inherited by a worker is no longer corrected.
- **OpenCode callers are no longer treated as Codex.** `--mode auto` falls back to headless when the Herdr caller pane cannot be verified, and an explicit pane request is refused before admission (issue #336).
- **A cancelled process group is now killed** after the TERM grace period, including members that ignored TERM.
- **A JSONL harness's result is now its last assistant message**, not an earlier interim one.
- **A status line that starts with `VAR=value` is refused** before settings are edited.
- **`superseded` is a new terminal takeover state**, recorded when `brgr head claim --abandoned` replaces a committed or resumed takeover. A script reading takeover states may see it.

## What changed

- **Revisions (#334, #337, #343).** A cancel marker from a cancelled or lost revision no longer cancels the next one. `brgr revise` recovers a clean worktree that no revision was admitted to, and cleans up after a failed admission. A refused revise no longer acknowledges the failure it was meant to replace.
- **Subdirectories (#335).** Captured diffs and worktree reclaim now cover a task started from a repository subdirectory.
- **Heads (#339, #345).** A head that was claimed can be claimed again after it disappears; older sessions are fenced by the binding epoch.
- **Error memo (#338).** Issue text masks paths whole, including most with spaces, and groups failures that differ only by path under one fingerprint.
- **Installers (#340).** Codex hook installs write through symlinks, and status line backups never overwrite an earlier backup.
- **Workflows (#344).** `workflow status` says when a driver has died and names the resume command. It does not change the run's state.
- **Config (#346).** `brgr config edit` and the set commands lock, reread and atomically replace the file, so concurrent changes are kept.
- **Docs (#333, #347).** Claims the review found wrong are fixed, and the review and its dispositions are kept in [the report](../evidence/gate-25-review-2026-11-05.md) and the readiness checklist.

## What was checked

- Full test suite, fmt and clippy on macOS, and CI on Linux.
- The runner fixes in one real OMP run.
- One real round through each tier 1 harness before tagging.

## Not checked

- The runner fixes through Pi.
- These fixes in live rounds on Linux, where only CI ran them.
- Cursor heads and Codex to Cursor handoffs, because Cursor's plan is at 96%.
- The resume of a legacy workflow driver record has no test.

## Known limits

- Gate 2-5 (a) stays open: the review did not read `caller_pane.rs`, `screens.rs`, `head_pane.rs`, `handoff_condition.rs` or the tests.
- Three P2s were left, none reproduced: a claim's five-second grace race, an admission lock race with pid reuse, and the error filer's lock and ledger parsing.
- A path in issue text with a differently spaced component, such as `/Users/a/my dir/x`, can stay partly unmasked.
- `cancelling_a_parent_stops_a_child_process_group...` has failed on CI and did not reproduce in twelve rounds under load. The cause is unknown.
- Some commands are still missing from the docs: `brgr errors`, `set-issue-reporting`, `config init/show/check`, `report`, `--max-children`, `--role-instruction`, `--scope`.
