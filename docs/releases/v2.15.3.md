# brgr v2.15.3

A patch for the Cursor owner inbox, plus two changes that touch only CI.

## Cursor owners get completion notices

A task owned by a Cursor head (`cursor:<CURSOR_CONVERSATION_ID>`) completed, but
its pane was never told. The owner pane was registered from the caller's shell
only for `claude:` owners, and the dispatcher that delivers the notice started
only for `claude:` owners. Both now include `cursor:`. Codex owners are unchanged.

## CI

- The tag job no longer runs `cargo fmt --check` and `cargo clippy`. The release
  pull request already runs them, and the tag follows a squash merge of that
  pull request. Measured on the v2.15.2 tag job, lint was about 28 seconds of
  roughly eight minutes; the rest is the clean-runner test run, the release build
  and the SBOM tool.
- `a_lost_run_whose_worker_still_runs_cannot_be_revised_until_it_stops` waits for
  a release file instead of sleeping four seconds, which failed when the runner
  was slow.

## Verified

Unit and black-box tests pass. A new test covers the dispatcher change and fails
without it. In a real Cursor pane with a scratch home, `FROM BRGR brgr_completion`
arrived in the conversation after the fix and did not before. The registration
change is checked only in that live pane, not by a test. The tag job without lint
has not run on a real tag until this release.

## Upgrade

```sh
cargo install --locked brgr-cli --version 2.15.3
brgr integrate claude install
herdr plugin install justn-hyeok/brgr --ref v2.15.3
```

No store migration. The macOS archive remains unsigned and not notarized.
