# brgr v2.12.5

Hotfix for a misleading note from v2.12.0's worktree reclamation.

## Fix

- When a pane task is decided, both the decision and the pane's session loop
  reclaim its worktree once the pane closes. If they ran at the same moment,
  the slower one failed to remove what the other had just removed and printed
  "kept worktree …: git declined to remove the worktree", although nothing was
  kept. Reclamation now holds a per-revision lock (`runs/<task>-r<n>.reclaim.lock`)
  and steps aside silently while another process holds it. A worktree that is
  already gone when a failure would be reported is not reported as kept.

## Upgrading

Install v2.12.5.

```sh
herdr plugin install justn-hyeok/brgr --ref v2.12.5
```

The CLI archive remains unsigned and not notarized.
