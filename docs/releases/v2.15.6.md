# brgr v2.15.6

Roadmap 2.6, complete: when a head's context window or plan usage passes a limit
you set, it hands its command to the harness you named, and the handoff is the
same verified one as before. Claude Code, Codex and Cursor each work as the head.

## Usage from every harness

| Harness | Source | Reports |
| --- | --- | --- |
| Claude Code | status line, `brgr integrate claude install --context` | context window, five-hour and seven-day plan |
| Cursor Agent | status line, `brgr integrate cursor install` | context window |
| Codex | the brgr hooks read the end of the session's rollout file | context window, five-hour and seven-day plan |

The two status-line installs put `brgr __context` in front of the status line you
have and run yours with the same input. Only the `statusLine` member of the config
file is edited, as text, after a backup, and `uninstall` restores it byte for byte.

## Telling, or doing

`brgr config set-handoff-condition --kind codex --context-percent 70
--quota-percent 85 --exit-old --agent-arg=--yolo` still tells the head, once per
crossing, with the exact command. Add `--auto` and the head's own brgr command
runs that handoff itself, from the head's verified pane. brgr never picks the
harness, never accepts a result, and closes a pane only with `--exit-old`. With a
plan limit set, a target whose own plan is already at it is named instead of
handed to.

## Two fixes found by running it

- A completion notice for work that was running (or finished) around a handoff
  reached only the old head when the new head ran in another harness. brgr now
  records the pane a handoff opened for the new head, reports a Codex head's
  session to Herdr, and delivers to what the pane actually runs.
- If the old head had decided everything before the new one took command, the
  handoff stayed committed for ever, because the new head had no owner-side write
  to make. `head retire` now records it as resumed when the owner has no open
  task, undecided result or unanswered worker message.

## Verified

Unit and black-box tests pass, and each fix failed its test first. In real Herdr
panes, with a worker running during the handoff: a Claude head handed to Codex
(the completion notice reached Codex, which accepted the result), a Codex head
handed to Claude (the notice reached Claude), and a Cursor head handed to Codex.
Each head's usage came from its own harness, and the session each recorded was
the one brgr uses. Not checked: Cursor's status line during a very long single
turn, and Codex's figures right after a compaction.

## Upgrade

```sh
cargo install --locked brgr-cli --version 2.15.6
brgr integrate claude install
herdr plugin install justn-hyeok/brgr --ref v2.15.6
```

No store migration. A config with a `[handoff]` table is refused by older brgr.
The macOS archive remains unsigned and not notarized.
