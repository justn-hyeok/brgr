# brgr v2.15.18

brgr now runs on x86_64 Linux with real agents, debate no longer stalls, and a worker's children have a real boundary. GJC is gone.

## Before you upgrade

- **A worker needs `--enable-delegation` to start children.** Pane mode used to enable it silently, so if your workers start their own workers, add the flag.
- **`brgr cancel TASK` stops the whole subtree**, not just that task. It lists what it stopped.
- **GJC is removed.** A registered `local.gjc` and a config section for it keep loading, and running it is refused.
- **`brgr debate wait` exits 0 on a timeout**, with a receipt, where it used to exit with an error.

## What changed

- **Linux.** A release archive for x86_64 Linux with checksums, and the Herdr plugin installs there. See what was checked below for how far that goes.
- **Debate (issue #301).** A member blocked in `message wait`, `wait` or `watch` returns early for a debate message. In real panes a blocked member answered in 4 to 13 seconds, against about 8 minutes reported. `debate wait` says when a debate starts during it. `debate status` shows unread age, worker state and blocking waits. `debate send` refuses a finished member, and every debate subcommand has help.
- **Codex workers know who they are.** A Codex worker's commands run in Codex's shared daemon, so it never had its identity and could not start a child or join a debate as itself. A task directory in a brgr worktree now names the worker and its pane.
- **Children (issue #302).** `status` and `result` reach every descendant, with its parent and model, for an ancestor's owner. Decisions stay with the direct owner. A child its parent cancelled no longer fails that parent, and an undecided child's error names the child and the command.
- **Aliases (issue #308).** `brgr config alias set astra --harness local.codex --model gpt-6-astra`, then `brgr run "..." --use astra`. Names may be Korean. A task stores the expanded route, so editing an alias changes no old task.
- **Screens.** Rules for Codex's hook review and Claude Code's fullscreen renderer offer. A worker on a fresh install stopped at each.
- **Sleep (issue #259).** A headless deadline keeps counting awake time, and its result records `slept_seconds`. A pane deadline is wall-clock time, and both are now documented.
- **Harness tiers (issue #307).** Tier 1 is Claude Code, Codex CLI, Cursor CLI and Devin CLI. Each release runs a real round through them first.

## What was checked

- Full test suite, fmt and clippy on macOS and Linux.
- [Real agents on Linux](../evidence/linux-real-agents-2026-11-05.md): a Claude Code head with all four tier 1 workers, and Codex and Cursor heads, each through start, sealed result, notice, accept, apply and cleanup, repeated on this release's code.
- [Debate, handoff and delegation in real panes](../evidence/debate-handoff-delegation-2026-11-05.md): debates across all four harnesses, head handoff in four directions, the delegation boundary, and cancel ending a tool under a child.
- [PTY proxy spike](../evidence/pty-proxy-spike-2026-11-04.md) and [its Linux run](../evidence/pty-proxy-spike-linux-2026-11-04.md): a go for the plain-terminal work in v3, which is not in this release.

## Not checked

- Real debate, delegation and handoff rounds on macOS. Unit and contract tests run there, and the author uses brgr there daily.
- aarch64 Linux, and distributions other than Ubuntu 24.04.
- A real machine sleep, conditional handoff, and Codex to Cursor or Cursor to Codex handoff.

## Known limits

- A first prompt can still be lost behind a screen no rule answers, and the worker then seals a report saying it had no objective (issue #316).
- A workflow step's `retries` needs the outcome `failed`, and a pane worker that dies or writes no report ends `lost`, so `retries` may rarely fire in a pane.
- A tool that a Codex worker runs lives in Codex's shared daemon, so a cancel cannot reach it.
- No human has reviewed this code; readiness gate 2-5 is still open.
