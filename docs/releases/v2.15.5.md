# brgr v2.15.5

The first half of roadmap 2.6: a head is told when its own usage passes a limit,
so it can hand its command to another harness before it runs out. Only Claude
Code reports figures in this release.

## What it does

`brgr config set-handoff-condition --kind codex --context-percent 70
--quota-percent 85 --exit-old --agent-arg=--yolo` names the harness that takes
over and the limits. When the head's context window, or either plan window, is at
or over a limit, the next brgr command it runs ends with one note on stderr that
carries the exact `brgr head handoff` command. The head runs it. brgr never runs
the handoff, never picks a harness, and never closes a pane itself, because the
handoff needs a verified pane and the owner's approval flags.

The note is given once per crossing, again after 30 minutes if the head is still
over, or after the head dropped 15 points below the limit and came back. It is not
given for a figure that is unmeasured or older than 30 minutes, for a head already
in the target harness, for a session that is not the owner's bound session, or
while a handoff is open.

## Where the figures come from

Claude Code hands its status line command the session's context-window fullness
and both plan windows (five-hour and seven-day). `brgr integrate claude install
--context` makes `brgr __context` that command. It records the figures under
`$BRGR_HOME/context/` and runs the status line you had with the same input, so it
looks the same. This edits `settings.json` (or the file it links to) and is
therefore opt-in. Only the `statusLine` member changes, as text, after a copy under
`$BRGR_HOME/backups/`. A status line that uses shell operators is refused, and
`uninstall` restores the previous member exactly and leaves one you changed.

## Verified

Unit and black-box tests pass, including a test that runs the installed command
the way Claude Code's shell does, with a path containing spaces. In real Herdr
panes with a scratch home and config: the chained status line drew, the figures
were recorded, the note appeared once on the first brgr command with the exact
command, the Claude head ran it, a Codex head took command, accepted and retired,
and the outgoing pane closed. Installing into a copy of a real managed
`settings.json` changed only the `statusLine` member and uninstall restored the
file byte for byte. The status line's `session_id` equals `CLAUDE_CODE_SESSION_ID`.

## Not in this release

Codex and Cursor figures (Codex writes them to its rollout file, Cursor to a
status line of the same shape as Claude's), the incoming harness's own usage, and
running the handoff without the head. A config with a `[handoff]` table is
refused by older brgr, like the other optional tables.

## Upgrade

```sh
cargo install --locked brgr-cli --version 2.15.5
brgr integrate claude install
herdr plugin install justn-hyeok/brgr --ref v2.15.5
```

No store migration. The macOS archive remains unsigned and not notarized.
