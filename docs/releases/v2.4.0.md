# brgr v2.4.0

This minor release makes worker questions work end to end, adds `brgr prune`,
and fixes the concurrency and scaling defects measured since v2.3.1.

## Workers can ask their owner

- Every managed worker can now ask its owner a question with `brgr message`.
  Before, only a task started with delegation gave its worker the identity and
  instructions to do so, so a plain `brgr run` worker could not ask at all.
  The instructions are appended after the task, so the task's first line (for
  example an OMP objective's `FROM CODEX`) is unchanged.
- When a worker asks, an idle Codex owner in Herdr receives a `FROM BRGR`
  notice of type `brgr_question` with the `message_id` and the commands to
  answer it. It is sent once per Codex session. Outside Herdr nothing is
  pushed; `brgr status TASK --tree` shows unanswered questions.
- Delegation is still a permission. A worker whose task was not started with
  delegation is refused if it tries to start a child task.

## Reclaiming worktrees

- `brgr prune` reports task worktrees whose revision has a recorded owner
  decision, and removes them with `--apply`. It also removes the `brgr/task-*`
  branches left behind when a worktree was deleted by hand. Sealed results,
  decisions, artifacts, and task rows are never removed.
- It never forces git. It refuses symlinks, locked worktrees, the current
  directory, and worktrees holding ignored files unless `--include-ignored`
  is passed. It acts only on paths the store records as created by brgr, in
  the repository each task came from.

## Reliability

- Concurrent task admissions no longer fail with a raw `database is locked`
  after their harness has already run. Write paths a running attempt depends
  on are retried under contention; the rest fail fast by design.
- The Herdr board stays fast as tasks accumulate: 6,400 stored tasks took
  3.26 s per refresh before and 11.5 ms after.
- A read-only command no longer takes the store's write lock because another
  build's schema stamp differs.
- A harness manifest whose result source is `stdout` or `jsonl_assistant_final`
  but carries a `path` is now refused instead of silently reading stdout.
- Every subcommand and global option is described in `--help`.

## Upgrading

- The store gains two tables, `task_checkouts` and `question_notices`. They are
  created the first time v2.4.0 opens an existing store.
- Run `brgr integrate codex install` after installing, so the Codex skill describes
  question notices.
- For tasks created before v2.4.0, brgr did not record the repository they
  came from. `brgr prune` still finds such a repository when any of its
  worktrees survive. When none do, the directory is reported and its branches
  have to be removed with `git branch -d`.

## Known limits

This release was made at the owner's decision with two release-review gates
still open: no review of the whole codebase by someone other than its author
at this release's commit, and two performance claims backed by tests rather
than benchmarks. See the
[readiness checklist](../readiness/v1-readiness-checklist-2026-09-14.md).

Install the Herdr plugin on Apple Silicon macOS 15 or newer:

```sh
herdr plugin install justn-hyeok/brgr --ref v2.4.0
```

The CLI archive remains unsigned and not notarized.
