# brgr v2.8.0

This minor release lets `brgr prune` delete task branches that only looked
unmerged.

## Prune deletes task branches whose commits survive elsewhere

- A task started from a feature branch carries that branch's commits. Once you
  went back to `main`, `git branch -d` called the task branch unmerged, and
  prune kept it forever.
- A task branch now goes when every commit on it is in `HEAD` or on another
  branch or remote-tracking branch.
- Other `brgr/task-*` branches do not count as a copy, since the same sweep may
  delete them too. A branch holding a commit found nowhere else is still kept,
  and prune says so.
- Deletion still refuses a branch some worktree has checked out. A branch that
  moves while it is being deleted is restored.

## Upgrading

No manifest or configuration change. Install v2.8.0 over v2.7.1. The first
`brgr prune --apply` may delete task branches it used to keep; run
`brgr prune` first to see the report.

The known limits of v2.4.0 still apply; see the
[readiness checklist](../readiness/v1-readiness-checklist-2026-09-14.md).

Install the Herdr plugin on Apple Silicon macOS 15 or newer:

```sh
herdr plugin install justn-hyeok/brgr --ref v2.8.0
```

The CLI archive remains unsigned and not notarized.
