# brgr v2.13.0

Four new workers: Codex CLI, GitHub Copilot CLI, Gemini CLI and Pi.

## Workers

| Harness | Id | Print mode | Full permission | Model | Effort |
|---|---|---|---|---|---|
| Codex CLI | `local.codex` | `codex exec --skip-git-repo-check --ephemeral` | `--dangerously-bypass-approvals-and-sandbox` | `--model` | `-c model_reasoning_effort=…` |
| GitHub Copilot CLI | `local.copilot` | `copilot --silent --prompt` | `--yolo` | `--model` | `--reasoning-effort` |
| Gemini CLI | `local.gemini` | `gemini --skip-trust --prompt` | `--approval-mode yolo` | `--model` | — |
| Pi | `local.pi` | `pi --print --no-session` | none needed (Pi asks no approvals) | `--model` | `--thinking` |

Each runs as its own TUI in a Herdr pane by default (Herdr kinds `codex`,
`copilot`, `gemini`, `pi`). Each was registered and taken through a real pane
task on Codex CLI 0.160.0, Copilot CLI 1.0.86, Gemini CLI 0.62.0 and Pi 0.73.1:
review a file, report, accept, and see the pane, worktree and branch go.

## Details

- **Codex as a worker.** Codex runs every hook in `~/.codex/hooks.json` for
  every session, and brgr installs hooks there for Codex owners. A worker
  Codex would have been bound as an owner and told to call brgr as one. Worker
  Codex now runs with `--disable hooks`. Checked live: no owner binding was
  added for a worker session, and a plain Codex session started while a worker
  ran still had its hooks run.
- **Trust prompts.**
  - Copilot asks "Do you trust the files in this folder?" even with `--yolo`.
    The new `copilot-trust` rule answers "Yes" only when the path in the
    prompt is exactly the task workspace.
  - Codex started in a task worktree says trust applies to the repository
    root. The `codex-trust` rule now accepts that only when the root is
    exactly the repository the worktree was checked out from.
  - Both rules are tested against captured screens.
- **Gemini CLI** drops its approval mode back to "default" in a folder it
  does not trust, so it runs with `--skip-trust`.

## Upgrading

Install v2.13.0, run `brgr integrate codex install` and
`brgr integrate claude install`, and register the workers you use, for
example:

```sh
herdr plugin install justn-hyeok/brgr --ref v2.13.0
brgr harness add "$(command -v copilot)" --workspace ~/brgr-scratch --prompt "Reply with OK"
```

Each CLI must be installed and logged in first. The CLI archive remains
unsigned and not notarized.
