# brgr v2.13.4

brgr on crates.io, a notice for a stale registration, and headless revisions.

## Fixes

- **A stale registration ran without telling you.** A harness registered
  before a recipe change kept its old certified launch: an OpenCode 2 harness
  registered by v2.13.2 still ran headless without `--standalone`, while its
  pane launch already used the new one. brgr now prints a one-line notice on
  each run until the harness is registered again, and names the command to do
  it. The certified launch is still what runs; brgr never swaps in a launch no
  scratch run certified. Checked live: an old Gemini registration printed the
  notice, and Pi, after it was registered again, did not.
- **A revision of a headless run asked the TUI for its model.** Revising a
  headless task that named a model was refused unless `--headless` was given
  again, because OpenCode 2's TUI takes no model. A revision of a headless run
  now stays headless.

## crates.io

brgr is published on crates.io: `cargo install --locked brgr-cli` installs the
`brgr` binary. The five internal crates (`brgr-core`, `brgr-protocol`,
`brgr-registry`, `brgr-runner`, `brgr-store`) are published alongside it and
are not a supported library API.

## Also in this release

- A burger icon in the README, issue and pull-request templates, and a code of
  conduct.
- The README and CONTRIBUTING no longer describe v2 as experimental.

## Upgrading

```sh
herdr plugin install justn-hyeok/brgr --ref v2.13.4
```

A harness that now prints the stale-registration notice needs
`brgr harness add PATH --workspace ~/brgr-scratch --prompt "Reply with OK"` once.

The CLI archive remains unsigned and not notarized.
