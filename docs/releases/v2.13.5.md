# brgr v2.13.5

Re-certifying an updated harness in one command, and failures that say why.

## Fixes

- **An updated harness stopped every run with a command you had to assemble.**
  A harness CLI that updates changes its executable or probe evidence, and the
  stop message named `brgr harness add PATH --workspace <dir> --prompt <prompt>`
  with the placeholders unfilled. `brgr harness recertify HARNESS` now
  registers it again at the path it was certified with, using one `say ok`
  scratch run, and the stop message is that command. Checked live on Cline.
- **A failed scratch run said nothing about why.** GJC reports a spent quota as
  an `errorMessage` event on stdout and leaves stderr empty, and brgr's reduced
  stream dropped it, so the failure read `exit code 1, 0 stderr bytes`. A run
  and a scratch run now quote one bounded line of it, for example `last error
  event: Connect error resource_exhausted: Error`. The quote is never copied
  into the error memo or an issue. Checked live on GJC.
- **Asking Cline for a model gave no way forward.** Cline 3.0.70 still saves an
  unknown `-m` as its default model, so brgr keeps refusing `--model` for it
  (and for Devin), but the refusal now names the command that changes the
  setting: `cline auth -m <model-id>`.
- **A Cline run recorded no model.** A harness that takes no model per run
  silently follows its own settings, so a changed default changed the model
  unnoticed. A successful Cline run now records the model its settings name,
  labelled `harness_config` rather than observed. Checked live on Cline.
- **A call that named no harness quietly ran GJC.** It now uses the configured
  default, else the only registered harness, and otherwise stops and lists the
  registered ones.

## New

- `brgr config set-auto-recertify true` (off by default) lets a new run or a
  revision re-certify an updated harness itself, in an empty temporary
  directory, and prints a warning each time. It is a paid scratch run that
  trusts the changed binary, so it is off unless you turn it on, it is refused
  through the Herdr host bridge, and a failed re-certification still stops the
  run. A config file that sets it is refused by older releases.
- GJC is marked experimental in the README and the reference. Registered GJC
  harnesses keep working.

## Upgrading

```sh
herdr plugin install justn-hyeok/brgr --ref v2.13.5
```

If you have several harnesses registered and relied on GJC being the default,
pass `--harness ID` or set `harness` under `[defaults]` in the brgr config.

The CLI archive remains unsigned and not notarized.
