# brgr v2.7.0

This minor release lets `brgr prune` reclaim the checkouts of runs that failed.

## Prune reclaims failed, cancelled, and lost runs

- Until now a worktree was reclaimed only after an owner decision, and only a
  successful candidate can be accepted or rejected. The checkout of every
  failed, cancelled, or lost run therefore stayed forever.
- Such a revision now counts as settled once its owner acknowledged the result
  with `brgr result TASK --ack`, no attempt of it is still running, and no
  retry was granted.
- A lost run's harness can outlive its supervisor. While the supervisor or the
  harness process recorded for the task is still alive, the worktree is kept.
- A kept worktree says what is missing, including the `--ack` command to run.
- Everything prune already refused is still refused: uncommitted or ignored
  files, locked worktrees, and unmerged branches. Sealed results, decisions,
  and task rows are never removed.

## Upgrading

No manifest or configuration change. Install v2.7.0 over v2.6.1. The first
`brgr prune --apply` may remove more than before: every acknowledged failure's
clean checkout. Run `brgr prune` first to see the report.

The known limits of v2.4.0 still apply; see the
[readiness checklist](../readiness/v1-readiness-checklist-2026-09-14.md).

Install the Herdr plugin on Apple Silicon macOS 15 or newer:

```sh
herdr plugin install justn-hyeok/brgr --ref v2.7.0
```

The CLI archive remains unsigned and not notarized.
