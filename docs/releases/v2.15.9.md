# brgr v2.15.9

A harness probe can no longer outlive a killed brgr and fill the disk.

## What changed

- A probe (`--version`, `--help`, the model catalog) now reads its output over
  pipes instead of temporary files. The probe runs in its own process group, and
  the files were watched only by the brgr process that started it. When that
  process was killed mid-probe, the probe kept writing to a file nobody watched.
  A pipe closes with its reader, so an orphaned probe ends on its next write.
  The 64 KiB output limit and the deadline are unchanged, and a probe that passes
  the limit is still stopped at once.
- Tests only: the probe flood test used an endless writer and now uses a finite
  one; two bridge tests no longer fail under heavy CPU load.

## Why

A full-workspace test run on one machine left a 909 GiB file and filled the disk.
The scratch directories it left behind showed the test process had died with the
flood running, so the writer was orphaned. Killing a parent mid-probe reproduced
it: the child survived in 12 of 12 runs. After the change a regression test kills
the parent and the child ends.

What is not known: what killed the test process that time.

## Compatibility

No store or config change. Probe results are the same; only how the output is
carried changed.
