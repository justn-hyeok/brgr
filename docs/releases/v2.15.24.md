# brgr v2.15.24

The repository moved to `sorrellabs/brgr`, the crates.io page's links work, and `harness add` prints the receipt it stored.

## Before you upgrade

- **The repository moved.** brgr now lives at `https://github.com/sorrellabs/brgr`. The old `justn-hyeok/brgr` address redirects web, git and API requests, so existing clones, installed Herdr plugins and issue-reporting settings keep working. To point a clone at the new home: `git remote set-url origin https://github.com/sorrellabs/brgr.git`. To move an installed Herdr plugin:

  ```sh
  herdr plugin install sorrellabs/brgr --ref v2.15.24
  ```

## What changed

- **Repository URLs (#396).** `Cargo.toml` `repository` and `homepage`, the README install commands, the guides and the release workflow name `sorrellabs/brgr`. crates.io picks up the new address with this publish. Evidence, past release notes and the changelog keep the address they were written with.
- **README links on crates.io (#397).** crates.io rewrote the README's relative links against `crates/brgr-cli/`, so every link on the brgr-cli page returned 404. They are absolute now and work on GitHub and crates.io alike.
- **`harness add` output (#398).** The printed receipt is the one stored on disk, including the `registered_path` added in v2.15.23. Before, the output was taken before that field was written.

## What was checked

- Full test suite, fmt and clippy on macOS, and CI on Linux.
- #398's regression test was checked by running it against the code before the fix and watching it fail.
- One real round through each tier 1 harness before tagging.

## Not checked
