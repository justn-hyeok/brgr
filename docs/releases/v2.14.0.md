# brgr v2.14.0

OpenCode 2 model selection in the native TUI, and the execution model roadmap.

## OpenCode TUI model selection

`brgr run ... --harness local.opencode --model provider/model#variant` now works
in the native TUI with the registered OpenCode 2 standalone recipe. It no longer
requires `--headless` just to select a model. A configured model uses the same
path; a separate TUI `--effort` remains unsupported.

brgr starts a temporary private loopback server, waits for the task location's
model catalog, checks the requested model and variant, creates a selected
session and reads it back. It stops that server before opening the TUI with
`--standalone --session SESSION`. Global and project configuration stay unchanged.

Missing models or variants, conflicting session/server/model calling arguments,
failed preparation and mismatched read-back stop the run. There is no implicit
model substitution, headless fallback or acceptance decision. The temporary
server exits when its host connection closes, and preparation has bounded
deadlines and output.

Checked locally on OpenCode 2.0.20: the native host displayed Cat Jam, the session
retained `opencode/cat-jam-free#high`, an unknown model was rejected before TUI
launch, and the temporary server exited after host death. This verifies selection
and lifecycle; it is not a live provider-response or full Herdr worker-completion
test. Regression tests cover session preparation, variant/read-back failures,
calling-option conflicts, output bounds and configured TUI models.

## Execution model roadmap

The [roadmap](../guides/roadmap.md) records the planned order: current quality,
continuity foundations, Head Migration, Dynamic Workflows, then their integration.
Head Migration and the Workflow Runtime are future plans, not features shipped
in this release. The existing managed-run contract remains unchanged.

## Upgrade

```sh
cargo install --locked brgr-cli --version 2.14.0
herdr plugin install justn-hyeok/brgr --ref v2.14.0
```

An existing OpenCode 2 registration with the native standalone recipe can use
the new path after upgrading brgr. Other commands behave as before. The macOS
archive remains unsigned and not notarized.
