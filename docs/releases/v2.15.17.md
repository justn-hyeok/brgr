# brgr v2.15.17

A worker's edit can no longer vanish from its sealed diff on Linux, `accept` no longer warns about cleanup another process finished, and a large objective can come from a file. Linux is still not a supported platform, but brgr's own tests now pass there.

## What changed

- **Sealed diff (issue #289).** On Linux an edit that kept a file's size, made in the same second as the checkout, could be missing from the sealed patch. The run looked like a normal `candidate`, and `brgr land` reported success having applied nothing. The work stayed in the kept worktree. brgr copied the Git index before diffing, and the copy's fresh time told Git to trust the file's size and time. The copy now keeps the index's time.
- **`accept` warning (issue #265).** `brgr cleanup pending: No such file or directory` no longer appears when the pane's session loop finished the same cleanup first. A report missing or unreadable for another reason is reported once, naming the path, and any remaining `cleanup pending` error names its file. A decision's reclaim also no longer keeps a worktree for good when it runs before the report is archived.
- **`brgr run --objective-file PATH`.** An objective up to 256 KiB can come from a regular UTF-8 file. Linux caps one argument at 128 KiB. The workflow SDK uses a private temporary file for tasks over 64 KiB.
- **Linux pane check.** The check that no ancestor process claims a different pane did nothing on Linux, because procps rejects `ps -E`. It now reads `/proc/PID/environ`. macOS is unchanged.
- **Worktree creation** retries when `git worktree add` meets another worktree still being created.
- **`HERDR_BIN_PATH`** is honored by the worktree creation, pane cleanup and OMP agent lookup commands too.

## For contributors

- The test suite no longer reaches a real Herdr from inside a Herdr pane, where it could send a real agent a `FROM BRGR` notice for a task that does not exist (issue #270).
- A pull request runs on Linux, in about two minutes. It took about eight on macOS. The macOS job runs on the push to `main`, so a macOS-only break is found after merge and before any release.
- A release waits for its commit's `main` run instead of repeating the tests.
- Readiness gate 2-4 is closed. Gate 2-5, a full non-author review, is still open.

## What was checked

- Full test suite repeated on CI: macOS 40 of 40 and, with the fixes in, Linux 20 of 20. These runs carried the tests and fixes up to the last Linux repeat; only the release commit's version bump came after. `main` passed on both before this release.
- Sealed diff: the new test fails on Linux without the fix and passes with it. The land test that first showed the bug passed 600 runs across 6 processes with the fix.
- Multi-process tests: 25 of 25 runs on Linux, with no product defect found.
- Fresh home on Apple Silicon macOS with the build of `main`: `integrate`, `harness add` with a real Cursor Agent, `doctor` printing `ok`, then a real pane worker that edited a file, reached `candidate`, showed its change in the sealed diff and landed it. The pane closed, and the worktree and task branch were then gone.
- Linux: one disposable VM with real Herdr 0.9.5 and the test fixture, confirming the pane lookup, the pane check refusing a false claim, and `--objective-file`. See `docs/evidence/linux-feasibility-2026-11-03.md`.

What was not checked: a real agent as head or worker on Linux (issue #284), how often the sealed-diff bug hit real runs, macOS on a non-APFS disk, and the new release gate before this release, which is its first real run. The suite was not repeated under load on a large development machine.

## Compatibility

No store schema or config change. `--objective-file` is additive. Scripts matching the old `cleanup pending` text see the file path added.
