# brgr v2.12.16

Hotfix found by a clean-install run: pane tasks could keep their worktree.

## Fix

- When a decision lands while the worker's pane is still busy, the pane's
  session process closes the pane later and reclaims the worktree. That
  process inherited the pane runner's working directory, which is the task
  worktree, so reclamation's own check ("this is the current working
  directory") kept the worktree, and the marker from v2.12.10 stopped any
  retry. Found by following the README on a fresh control home: the first
  task's clean worktree stayed after `accept`.
- The session process now starts in the brgr control home, and reclamation
  moves out of the worktree before assessing it, so whichever process runs
  it, it can reclaim.

## Upgrading

Install v2.12.16. Worktrees an earlier version kept this way are listed as
removable by `brgr prune` and removed by `brgr prune --apply`.

```sh
herdr plugin install justn-hyeok/brgr --ref v2.12.16
```

The CLI archive remains unsigned and not notarized.
