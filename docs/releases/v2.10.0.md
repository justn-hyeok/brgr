# brgr v2.10.0

This release makes brgr run its workers unattended: nobody has to click a
worker's screen, every worker runs with full permissions, messages reach owners
and workers in both directions, and a failed run reaches its owner at once.

## Changes

- **Workers run as their own TUI with full permissions.** The default is the
  harness's native TUI in a Herdr pane with its full-permission option
  (`--yolo`, `bypassPermissions`, and equivalents). `--permission` and the
  `permission` config key are accepted and ignored with a note;
  `config set-max-permission` and `clear-max-permission` are removed. Custom
  manifests may carry permission flags.
- **Screens that would stop a worker are answered.** A rule table accepts the
  folder-trust prompt for the task's own workspace (Claude Code, Codex),
  "press Enter to continue" notices, Claude Code's Bypass Permissions warning
  and new-MCP-server prompt; it skips update offers and dismisses an
  already-applied self-update. Nothing is pressed while the agent works. A
  screen no rule covers is reported to the owner and fails the run after three
  minutes with its text. Every key brgr presses is logged to
  `runs/<task>-r<rev>.screens.log`. OpenCode and Claude Code start with their
  self-update disabled.
- **Messages in both directions.** Owner messages are delivered into the
  worker's TUI; worker questions are pushed to an idle owner. Claude Code
  sessions are owners too (`claude:<CLAUDE_CODE_SESSION_ID>`).
- **Failures reach the owner.** A failed or lost run is pushed as a
  `brgr_failure` notice with its reason, and every brgr command the owner runs
  ends with a stderr note listing unacknowledged failures until
  `brgr result TASK --ack`.
- **Error memo.** Failed and lost runs are folded into
  `$BRGR_HOME/brgr_error_issue_memo.md`. `brgr errors`, `brgr errors preview`
  and `brgr errors file`; GitHub issue filing is off until
  `brgr config set-issue-reporting OWNER/NAME`, and issue text holds only the
  redacted error class and counts.
- **Codex callers are placed by what the panes show.** With several Codex panes,
  a call is attributed to the one Codex pane whose screen shows
  `Ran brgr --as <session>`; Herdr's recorded session for a pane is no longer
  trusted. The hook tells Codex to start brgr commands with `--as SESSION`
  (an alias of `--owner-session`). The worker pane opens once the call shows on
  a screen; a wide caller gets its worker beside it, a narrow one below it.
- **An agent that stops without a report** is sealed if it wrote one, reminded
  once otherwise, then failed with the cause instead of waiting for the
  deadline.

## Behaviour changes to check

- `brgr wait TASK` returns early with `state: awaiting_input` while a worker
  question is unanswered, so an owner and a waiting worker do not block each
  other. Scripts that expect a terminal result must check `state`.
- The pane runner may wait up to 40 seconds for a Codex call to show on a
  screen before opening the worker pane.

## Upgrading

Install v2.10.0, then run `brgr integrate codex install`: each build changes the
Codex hook digest. Replace the binary by writing a new file and renaming it over
the old one; overwriting a signed binary in place made macOS kill it.

Install the Herdr plugin on Apple Silicon macOS 15 or newer:

```sh
herdr plugin install justn-hyeok/brgr --ref v2.10.0
```

The CLI archive remains unsigned and not notarized.

## Known limits

- A Codex pane narrower than about 35 columns cuts the printed command before
  the session id, so the caller cannot be placed and the run fails after 40 s.
- Herdr's own Codex hook records a new Codex session against the pane of the
  session that started Codex's shared daemon. brgr no longer uses that record,
  but a later overwrite can still stop a notice from being delivered (it is never
  delivered to the wrong pane).
- Not yet seen on a real harness screen: the update-offer, continue-notice,
  applied-update, bypass-warning and MCP rules (tested on written screens), and
  the Codex Stop hook with a failure pending.
