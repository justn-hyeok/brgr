# brgr v2.9.0

This minor release brings pane mode to every harness Herdr can host.

## Pane mode for Cursor, Devin, Cline, OMP, and OpenCode

- Inside Herdr, each of these now runs as its own interactive session in a pane
  beside the caller, as Claude Code already did. Each one was started in a
  real Herdr pane and completed a task before its recipe gained the launch.
- Cursor starts with `--trust` and Devin with `--respect-workspace-trust false`,
  as their print modes already do.
- OpenCode's TUI takes no effort flag, so an OpenCode task with `--effort` runs
  headless. The effort is honoured, not dropped.
- GJC and Command Code are not agents Herdr recognizes and stay headless.

## Pane mode handles a stuck startup

- An agent that starts on a screen Herdr cannot classify used to fail the run
  after a minute. Cline, for example, opens with a product notice that waits
  for a key. Now the owner gets a question naming the pane, and the run waits.
- A question a pane-mode run sends its owner is withdrawn once the agent is
  ready again. Before, the finished task failed with "question(s) remain
  unanswered" after someone dealt with the pane.

## Other changes

- Cline no longer takes `--model`. Cline 3.0.65 saved an unknown model name as
  its own default, which broke every later Cline run. Cline now runs its
  configured model, as Devin does.
- Harness registration's scratch run may take three minutes instead of one, so
  a slow free model can still be registered.

## Upgrading

Install v2.9.0, then re-register Claude Code, Cursor, Devin, Cline, OMP, and
OpenCode with `brgr harness add` to enable pane mode for them. A manifest that
records `effort_print_only` cannot be read by v2.8.0.

The known limits of v2.4.0 still apply; see the
[readiness checklist](../readiness/v1-readiness-checklist-2026-09-14.md).

Install the Herdr plugin on Apple Silicon macOS 15 or newer:

```sh
herdr plugin install justn-hyeok/brgr --ref v2.9.0
```

The CLI archive remains unsigned and not notarized.
