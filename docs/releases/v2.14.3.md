# brgr v2.14.3

A way to wait for workers without blocking the agent, and a sealed diff that says
when a worker left its changes in the shared git stash.

## `brgr watch`: wait without blocking the conversation

An agent that waited with `brgr wait` or a sleep loop was stuck in that call and
could not answer its user. `brgr watch TASK [TASK...]` is a command whose output is
the event stream, so any tool that can run a background command (Claude Code's
Monitor, a background terminal, a plain `&`) turns each line into a notification:

| Event line | Meaning |
| --- | --- |
| `{"event":"state","task_id":"...","state":"running"}` | the task's state changed (and once at the start) |
| `{"event":"question","task_id":"...","message_id":"..."}` | the worker has a new question for you, once per message |
| `{"event":"result","task_id":"...","outcome":"candidate","revision":1}` | the task has a sealed result, once per task |
| `{"event":"done"}` | every watched task has a result; the command exits 0 |
| `{"event":"timeout"}` | `--timeout-seconds` (default 3600) passed first; non-zero exit |

It only reads. It never decides, acknowledges or writes, makes no network or Herdr
call, prints only ids, states, outcomes and message ids, and checks that every task
belongs to the caller as `brgr wait` does. A task that already has a result reports
it at once. The embedded skill's wait step now tells an agent to run it in the
background; `brgr wait` still works and still blocks.

## A sealed diff says when work was left in a stash

`git stash` belongs to the repository, not to a worktree. A worker that stashed its
changes to compare with a baseline and did not pop them ended with a clean tree, so
the sealed diff silently missed its work, and a worker that popped "its" stash could
take another worker's. brgr cannot stop the git command, but a result no longer
hides it: for a task with `capture_diff`, `unresolved_effects` now says
`The worker left N entries in the git stash on brgr/task-...; changes held in a stash
are not part of this diff` when entries are on that task's own branch. Entries of
other branches do not count and stash messages are never quoted. If the stash cannot
be read the seal still succeeds and the note reads `could not check the git stash for
left-behind changes` (nothing is added for a workspace that is not a git repository).
The result stays a candidate; this adds a note and blocks nothing. The stash itself is
still shared; this reports it and does not isolate it.

## Dependency

tokio is updated from 1.53.1 to 1.54.1 for RUSTSEC-2026-0386 (an `unsound` advisory
on `AsyncFd`), which had started to fail the supply-chain check on every branch.

## Upgrade

```sh
cargo install --locked brgr-cli --version 2.14.3
brgr integrate claude install
herdr plugin install justn-hyeok/brgr --ref v2.14.3
```

`brgr integrate` refreshes the installed skill so it mentions `brgr watch`. No store
migration. The macOS archive remains unsigned and not notarized.
