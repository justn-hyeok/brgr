# brgr v2.13.1

Fixes from a code review of v2.13.0.

## Fixes

- **Codex workers keep the user's own hooks.** v2.13.0 ran worker Codex with
  `--disable hooks` to keep brgr's owner hook out of worker sessions. That
  also turned off every other hook, including any safety hook the user keeps,
  in a worker that already runs without approvals or sandbox. Now brgr's own
  hook reads the session's working directory, which Codex sends with every
  hook, and does nothing inside a brgr task worktree. Checked live with hooks
  on: a pane Codex worker added no owner binding.
- **A prompt starting with `-` or `@` stays text** in headless runs, where
  Codex, Gemini and Pi take the prompt as an argument: a markdown list read as
  options, and Pi read `@path` as a file include. It is now passed with a
  leading space. Pane runs paste the prompt and were not affected.
- **Copilot workers run with `--no-ask-user`**, so Copilot asks its owner
  through brgr instead of opening its own question dialog, which no screen rule
  answers.
- **Screen checks no longer run `git` every second.** The Codex worktree trust
  rule looks up the worktree's repository only when that prompt is showing.
- **More auth variables reach the new workers:**
  - Gemini: `GOOGLE_CLOUD_LOCATION`, `GOOGLE_APPLICATION_CREDENTIALS`
  - Codex: `CODEX_API_KEY`
  - Pi: OpenRouter, Groq, xAI, Mistral, DeepSeek and Cerebras keys
- **A failed headless run says why.** Its reason now ends with the harness's
  own stderr line, the first that reads like an error. A spent Gemini
  free-tier quota used to read only "process produced no result artifact".
  The error memo cuts the quote off, as it does a pane's last screen.

## Documented

- Codex offers no "this session only" trust. When a Codex worker starts in a
  task worktree, brgr accepts the prompt for the repository that worktree
  came from, and Codex saves that repository as trusted in
  `~/.codex/config.toml`.

## Upgrading

Install v2.13.1, run `brgr integrate codex install`, and register
`local.codex` and `local.copilot` again so they pick up the changed recipes:

```sh
herdr plugin install justn-hyeok/brgr --ref v2.13.1
brgr harness add "$(command -v codex)" --workspace ~/brgr-scratch --prompt "Reply with OK"
brgr harness add "$(command -v copilot)" --workspace ~/brgr-scratch --prompt "Reply with OK"
```

The CLI archive remains unsigned and not notarized.
