# brgr v2.5.0

This minor release adds worker permission levels and three new harnesses.

## Permission levels

- Every worker runs at a level: `full` (the default), `edits`, or
  `read-only`. Choose it per task with `brgr run --permission` or
  `brgr revise --permission`.
- Cap every task with `brgr config set-max-permission <level>`; remove the cap
  with `brgr config clear-max-permission`. A request above the cap, or above the
  parent task's own level, is refused rather than lowered.
- Each harness maps the levels to its own flags. A level a harness cannot
  honour is refused before anything runs; brgr never runs it under a wider one.
  A task that asks for nothing, with no cap, runs exactly as before.

## New harnesses

- Claude Code (`local.claude-code`), Cline (`local.cline`), and OpenCode
  (`local.opencode`).
- Claude Code and Cline have no model list brgr can check a name against before
  a paid run, so they use each CLI's configured default model, as Devin does.
  Effort remains selectable. OpenCode's models are checked against
  `opencode models`.

## Changed defaults

- Cursor no longer pins read-only `--mode ask`, and Command Code no longer pins
  plan mode and two turns. Both now default to the full level, like the others.
  Re-register a harness to pick up its new recipe.

## Fixes

- A failed harness registration says why: exit code, timeout, truncation, and
  output sizes.
- Help printed only to stderr, as `opencode run --help` does, is now read in
  registration and health checks.
- A notification dispatcher stops once its control home is removed.

## Upgrading

Manifests registered by v2.5.0 carry a field older versions cannot read.
Install v2.5.0 before registering or re-registering a harness.

The known limits of v2.4.0 still apply; see the
[readiness checklist](../readiness/v1-readiness-checklist-2026-09-14.md).

Install the Herdr plugin on Apple Silicon macOS 15 or newer:

```sh
herdr plugin install justn-hyeok/brgr --ref v2.5.0
```

The CLI archive remains unsigned and not notarized.
