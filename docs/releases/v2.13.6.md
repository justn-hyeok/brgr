# brgr v2.13.6

A worker's changes survive a missing report, and `apply` can merge.

## Fixes

- **A worker that never wrote its report lost its work.** A worker that edited
  files and then stopped without `report.md` was lost with no sealed diff, so
  `brgr diff` said `result has no sealed Git diff` and the only way back was to
  hand the same task out again. The diff of the worktree is now sealed with a
  failed or lost result (when the task asked for `--capture-diff`), so it can be
  reviewed and exported. The result still cannot be accepted.
- **`brgr apply` gave up on any conflict.** Four parallel workers that each
  appended an entry to the same document made every apply after the first
  fail with `patch does not apply`. `brgr apply TASK --workspace REPO --3way`
  now merges the sealed diff with the target's own changes, as `git apply
  --3way` does. A clean merge applies. A conflict is written as standard
  markers, the receipt records `applied_with_conflicts` with the files, and the
  command exits with an error so a script cannot take it for success. Without
  `--3way`, the failure now says to try it. A dry run reports
  `ready_with_conflicts` and touches nothing.
- **A failed model catalog probe was a dead end.** A transient failure of the
  catalog command refused the run with `bounded model catalog probe failed`.
  The probe is now tried once more, and a probe that still fails names the
  harness, the exit code or timeout, and one quoted line from the CLI. A start
  that takes more than a few seconds says which step it is waiting for. A
  three-minute start reported once was not reproduced, so its cause is not
  known; the step message will name it if it recurs.

## Also in this release

- `brgr status TASK --json` puts `workspace` and `base_commit` at the top level,
  and the reference lists the fields. brgr's own notes already go to stderr, so
  stdout is one JSON object; a test now holds that.

## Upgrading

```sh
herdr plugin install justn-hyeok/brgr --ref v2.13.6
```

`brgr apply` without `--3way` behaves as before.

The CLI archive remains unsigned and not notarized.
