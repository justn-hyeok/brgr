# brgr v2.14.1

Fixes for OpenCode model selection from a repository root and for a cleanup
warning that repeated forever, plus test isolation.

## OpenCode model selection from a repository root

In v2.14.0, `brgr run ... --harness local.opencode --model provider/model` failed
at once from a repository root: the worker ended `lost` with `OpenCode returned a
catalog for a different task location`. For a source at the repository root, the
task workspace path ended with a separator, and the model-selection step compares
the location OpenCode reports with the workspace as an exact string. The path no
longer carries the separator. A run from a subdirectory was not affected, and a
run without `--model` never reached this step.

## A changed handled report is reported once

When a worker's `report.md` changed after the owner had decided the result, the
archive step refused it, and every later brgr command printed `brgr cleanup
pending: handled report changed before archival` without saying which task. The
condition is permanent, so the retry and the warning never ended.

brgr now records the refusal on the pane receipt and prints one line naming the
task, revision and report path. The file stays where it is; brgr does not archive
or delete a report that no longer matches what the owner reviewed. Later commands
do not retry or warn. An older brgr that reads the same receipt ignores the new
field and goes back to the old repeated warning.

## Tests no longer depend on the shell

Run inside a brgr worker, the suite failed 98 of 120 `cli_contract` tests because
the spawned commands inherited `BRGR_PARENT_TASK_ID` and `BRGR_PARENT_ATTEMPT_ID`.
Inside a Herdr pane with `HERDR_SESSION` set, three `caller_pane` unit tests failed
because the fake `herdr` did not accept the `--session` flag. The tests now clear
the inherited identity per command and the fixture skips the flag. No product
behaviour changed. Verified: the suite passes in a clean environment, with the
worker variables set, and inside a Herdr pane; `plugin_bridge` timing can still
fail on a loaded machine and is not part of this change.

## Upgrade

```sh
cargo install --locked brgr-cli --version 2.14.1
herdr plugin install justn-hyeok/brgr --ref v2.14.1
```

No store or registration change. The macOS archive remains unsigned and not
notarized.
