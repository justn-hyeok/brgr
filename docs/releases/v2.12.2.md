# brgr v2.12.2

Hotfix for v2.12.0's worktree reclamation, which could delete a worker's
deliverable.

## Fix

- v2.12.0 treated an untracked `.claude/`, `.cursor/`, `.opencode/`, `.cline/`,
  `.devin/` or `.omp/` as a harness cache that never keeps a worktree. Those
  directories also hold project configuration: a task asked to add a Claude
  Code command writes `.claude/commands/…`, which git reports as the bare
  `.claude/`. Without `--capture-diff`, deciding that task force-removed the
  worktree and the new file with it. Only `.gjc/` and `.commandcode/`, which
  hold nothing but the harness's own session state, are caches now.

## Upgrading

Install v2.12.2.

```sh
herdr plugin install justn-hyeok/brgr --ref v2.12.2
```

The CLI archive remains unsigned and not notarized.
