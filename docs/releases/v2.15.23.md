# brgr v2.15.23

A harness registered through a symlink now survives a Homebrew upgrade, a macOS caller's pane is read only from its environment, and tests stop leaving a trampoline file per process.

## Before you upgrade

- **Register Homebrew-installed harnesses once more.** The activation receipt now keeps `registered_path`, the symlink a harness was added through (for example `/opt/homebrew/bin/claude`). Receipts written before this release do not have it, so run this once per harness installed that way:

  ```sh
  brgr harness add /opt/homebrew/bin/<cli> --workspace <scratch> --prompt "say ok"
  ```

  After that, a cask upgrade that deletes the old versioned directory can be followed by `brgr harness recertify`. Without it, recertify now fails with an error that names the missing path and this command, instead of a bare `No such file or directory`.
- **The receipt gains an optional field.** `registered_path` is omitted when it is not set; the schema stays `brgr.activation/v1` and older receipts still load.

## What changed

- **Recertify through the registered symlink (#390, #392, issue #388).** Launch and identity checks still use the realpath and digest. When the certified realpath is gone and `registered_path` resolves to a file, `brgr harness recertify ID` runs the full scratch certification through it and records the new realpath. With `config set-auto-recertify true`, a run whose harness became unspawnable this way re-certifies first and says so on stderr. A recertify while the realpath still exists keeps `registered_path`. An agent-authored manifest is never rewritten; it gets the same clear error.
- **macOS caller pane (#389, issue #279).** `ps -E` prints no environment for system binaries such as `/bin/zsh`, so a `HERDR_PANE_ID=` written in a process's arguments was read as its pane. brgr now runs `ps` without and with `-E` and reads only what follows the arguments line and a space; otherwise the result is unknown.
- **Test trampoline (#391, #394).** Tests share one `brgr-fast-script/trampoline-<hash>` instead of leaving one file per test process, and write the script directly when the shared inode reaches its hard-link limit.

## What was checked

- Full test suite, fmt and clippy on macOS, and CI on Linux.
- Each fix's regression test was checked by reverting the fix and watching it fail.
- The #279 parse was compared against every running process of this Mac's user: the arguments line plus a space prefixed every visible environment.
- One real round through each tier 1 harness before tagging, after registering Claude Code through `/opt/homebrew/bin/claude`.

## Not checked

- A real Homebrew upgrade of a harness after this change: #388 was verified with fixture tests that delete a versioned directory and repoint a symlink.
- #279 in a live Herdr owner pane whose ancestor quotes another pane's id.

- About 28 tests decide an outcome with a fixed sleep or a timer.
